# v0.1.1 — Security Hardening: Summary

Corresponds to `CHANGELOG.md` → v0.1.1. Follow-up to the gaps found in
`doc/v0.1-summary.md`'s security checklist — fixes only, no scope change
to what v0.1 captures.

## What changed

| File | Change |
|---|---|
| `src/storage.py` | `upload_audio()` now returns the Storage object **path**, not a public URL. New `get_signed_audio_url(path, expires_in)` generates a time-limited signed URL on demand. |
| `src/bot.py` | Stores the path returned by `upload_audio()` into `audio_url` (column name unchanged — still matches "audio file reference" from the v0.1 scope). |
| `src/get_audio_url.py` (new) | Minimal CLI: `python get_audio_url.py <path> [expires_in_seconds]` — prints a signed URL, default expiry 1h. This is currently the *only* way to actually listen to a captured voice moment; no retrieval UI exists yet. |
| `sql/002_enable_rls.sql` (new) | `alter table moments enable row level security;` — no policies added. `service_role` bypasses RLS entirely (unaffected); `anon`/`authenticated` keys get default-deny. Run manually in the Supabase SQL Editor. |
| Supabase Storage config | `voice-notes` bucket flipped from public to private via `update_bucket()`. |

## Why: path-only storage instead of a stored signed URL

A signed URL has a fixed expiry baked into its signature. Storing one
directly in `audio_url` would mean the column silently stops resolving
once that expiry passes — in tension with v0.1's own success criterion
("durably stored and **retrievable**"). Storing the raw path instead
never expires; a signed URL is generated fresh, on demand, whenever
someone actually wants to listen. Trade-off accepted: v0.1 has no
retrieval UI, so "retrievable" for now means running a one-line script,
not clicking a link — acceptable for a single-user personal tool at this
stage.
